# Nine-Shot Story Protocol｜3.1

文件名保留 v3 以兼容旧引用。九镜是故事覆盖与剪辑组织，不是必须发生九次转折。

## 1. 先锁原故事

读取 [story-state-continuity.md](story-state-continuity.md)，建立来源事实、不可改写项和关键实体状态。

- 原故事已有三段：可各分成三个动作/观看阶段，保留原顺序与结局。
- 现成三联锚帧：先核对锚帧事实是否自洽，再补过渡，不能擅自替换已批准画面。
- 原创冲突故事：可选择“建立—发现—证据—压力—决定—变化—后果—代价—余韵”，但只是候选结构；代价、反转、开放结局不再是必需项。
- 日常、抒情、产品与纪录题材：允许观察、接近、互动、停留形成节奏，不为了九镜强加事件。

源故事的关键事实必须映射到镜号；补充镜头注明作用。保持事实覆盖、动作连贯和观看信息，而非规定第 5 镜一定决定、第 8 镜一定失去什么。

## 2. 九镜账本

    镜号 | 来源事实 | 本镜功能 | 镜前→主要事件→镜后 | 关键实体 | 机位/拍向/轴侧 | 可见证据 | 依赖镜

当用户要视频提示词，另读 [video-motion-protocol.md](video-motion-protocol.md)，加入帧角色、摄影机/主体运动、焦点、尾态和剪辑衔接。不要用九次 still prompt 代替九段视频设计。

## 3. 节奏与摄影机

按全段安排空间、关系、细节、反应和停顿，不强制每种镜头的数量。景别与观看位置服务源故事。

- 建立必要的地理关系；交接前人物应已在可触及范围。
- 动作匹配与正反打允许重复构图，不要求每镜换四项。
- 判断镜头是否新增因果、关系、节奏或观看信息，而非只换焦段数字。
- 光源固定在世界中；转拍向后的屏幕变化应可解释。
- 特殊机位或复杂运镜需要有效空间和叙事理由，不为凑多样性制造未知背面。

场景资产或高风险机位读 [asset-space-protocol.md](asset-space-protocol.md)。

## 4. 单帧编译

每镜共同事实加当前状态，不复用一整份含旧状态的长提示词：

    独立单帧 + 用户指定媒介/比例
    本镜相关的身份与空间事实
    关键道具当前数量、持有人、位置和状态
    动作阶段 + 可见证据
    摄影机站位/拍向/景别与轴线
    决定性层次 + 光源/综合色/必要成像特征

关键帧只是动作的某一时刻。要作为视频首帧时，检查状态是否允许接下来的动作，不让已经交付的物件被重新交付。

## 5. 生成依赖与返工

1. 准备必要的画风、身份/空间参考及初始状态；保留已批准且符合故事状态的镜头，不重复生成。
2. 按依赖推进，可每三镜组织队列；关键转移/损坏镜先验收。
3. 每次落盘记录镜号、精确提示、输入及用途、状态和返回路径。
4. 只把已验收状态传给下游；不要初态母版覆盖后续状态，也不盲目链式继承错误。
5. 失败保留剧情功能，修相应镜，复核依赖它的后续镜。遵守主技能补跑上限。
6. 九张源图齐全后再外部拼版。

三批不是连续性的证明；文件数量也不是剧情通过的证据。

## 6. 验收顺序

先做硬门槛检查：

- 源故事核心事实与指定结局得到覆盖。
- 人物身份、必见角色及其化形阶段、道具数量和归属符合事件链；模糊意象不自动等于已具象化。
- 空间、脚点、接触距离、进出方向和视线成立。
- 相邻镜及远距离因果状态相容。
- 九张独立可读图，按批准比例输出；拼版顺序正确且不拉伸。

再看节奏、构图、色彩与媒介。每项记通过/失败/无法判断，不用审美平均分掩盖关键错误。没有独立盲读不称为盲测，没有生成视频不称为运动验收。

默认输出九张源图、三张纵向三联和一张 3×3 接触表；用户只要九镜文本或视频提示词时不自动生成这些图像文件。
