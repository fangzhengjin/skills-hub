# 视频动作与运镜协议｜3.1

用户要求视频提示词、图生视频方案或实际视频时读取。此协议是导演意图到后端提示词的编译流程，不是某个视频服务的 API 文档。

## 1. 判断任务与首帧

只要提示词就直接编写，不自动生成图、视频或购买服务。后端未指定时用中立写法并标明参数待适配；只有实际执行所需的能力、授权或资产缺失才需要暂停相应执行。

先检查输入图，不盲信文件名或前一轮说明：

| 帧角色 | 如何编写动作 |
|---|---|
| start：动作尚未开始 | 可以从该动作起点启动 |
| mid：动作进行中 | 从当前阶段继续，不让角色先复位重演 |
| end：动作已经完成 | 写下一步或停留；需要完整前序动作时另准备首帧 |
| reference：只有构图/身份用途 | 不冒充首帧；说明还需准备什么起始状态 |

交接双方已握住伞时，写“接住并松手”，不是“走近、找伞、递伞”。门已关时不能直接写继续关门。只有正面资产却要求绕到背面时，先处理未知空间。

人物已半跪成形时，可从半跪站起，不能复位为一团烟重演化形；人物已回望时，应保持或转回，而非再从朝前开始。画幅未展示的脚点/手部不能当作已核验状态；若关键动作依赖这些区域，先补足可见起始状态，或只设计现有构图可支持的动作。

九宫格/三联合成图先对应到独立镜头；不能直接当单镜图生视频首帧。检查源图是否清晰、关键手部是否完整、角色状态是否已正确，避免把错误动画化。

## 2. 每镜导演控制卡

内部保留足够信息，但不要把全部字段机械塞进最终短提示词。简单镜头可合并字段，关键动作不能省略首尾状态与验收。

```text
shot_id / source_beat / 本镜的信息目的
输入：路径或待提供；角色 start/mid/end/reference；可见状态
前提：依赖镜号、人物与道具 ID、空间假设
节奏：建议剪辑时长；起势→主要事件→落点；预留剪辑余量
主体：哪个人/物；世界方向与屏幕方向；一个主要事件；完成条件
摄影机：起始站位/拍向/高度；景别与透视意图
运镜：方式；相对谁移动；路径/方向；速度感；终点构图；何时停
焦点：固定目标或一次有意义的焦点转移；与机位运动分开
环境：必要的雨、风、水、背景动作；不抢主要事件
首态→尾态：数量、持有人、位置、姿态、开合、损坏、视线
衔接：进入/退出画方向；动作匹配/视线接续/重建空间/明确跳时
后端：已选版本或未指定；能力已核验/未核验；实际参数或仅意图
验收：关键可见证据、失败条件、未知项
```

`planned_duration` 是剪辑设计；`generation_duration` 是实际支持的生成时长。无后端时可以建议剪辑时长，但别伪造可提交的秒数。若需要取长片段再剪短，说明可用区间，不能因此省略关键事件。

时间分段优先写“先—随后—最后”的事件顺序。需要精确秒点时放在导演卡，短提示仅保留必要节奏；除非工具支持并验证，否则不声称逐帧可控。

## 3. 运镜选择：先目的，后名称

先选固定机位是否已经足够。默认一个主要运镜；合乎物理的轻微跟摇等辅助可以有，但要说清主次。用户明确要求复杂长镜头时可组合，增加路径、遮挡和首尾构图核验，不强拆成九个镜头。

| 意图/方式 | 必须说明的空间行为 | 易混淆处 |
|---|---|---|
| 固定观察 locked-off | 摄影机位置、拍向稳定；主体可动 | 固定不是画面内所有东西冻结 |
| 推/拉 dolly in/out | 相对主体靠近/远离；保持或改变拍向；终点景别 | 不把焦距变化当机位位移 |
| 横移 truck/lateral tracking | 沿主体哪一侧；与行走同向还是独立移动；距离关系 | 不等同原地摇摄 |
| 摇摄 pan/tilt | 摄影机位置不变；拍向由哪个可见目标转到哪个目标 | 不等同横移/升降 |
| 升降 pedestal/crane | 机位升/降；是否同步改变拍向；新增可见区域 | 不凭“上摇”制造越墙航拍 |
| 弧线 arc/orbit | 围绕什么；从哪侧到哪侧；轴线和背面可见性 | 不用无定义的“环绕 360°”填充导演感 |
| 变焦 zoom | 机位固定、视角范围改变；为何需要这种效果 | Dolly zoom 是另一种需专门设计的组合 |
| 拉焦 rack focus | 机位是否固定；焦点从谁到谁；两者都在画内 | 拉焦不是移动摄影机或移动物体 |
| 手持/稳定跟随 | 谁在观察；抖动程度、跟随距离和落点 | 不同时要求完全锁定与明显手持晃动 |

以上用于指导，不代表后端都精确支持。写焦段时说明是全画幅等效意图或仅透视参考；没有测量依据不要编造空间米数。术语用法可参阅 [Runway Camera Terms](https://help.runwayml.com/hc/en-us/articles/46749315925395-Camera-Terms-Prompts-Examples)。

主体方向用清楚的参照系：“在画面中从左向右走”“摄影机在桥的近侧平行跟随”。内部实体 ID 在短提示中编译为首帧可识别的人物位置/服装标签，不让后端猜 A/B 是谁。

手绘/动画的“推近、摇摄、横移”仍需区分相机意图与角色动作；不因使用摄影术语把画面变成真人或三维。保持既有线条、色块与纹理，只有题材允许时设计视差与局部运动；不把平面放大自动宣称为已实现真实相机位移。

## 4. 首尾状态与剪辑

一镜内允许状态随动作改变，但不允许靠换脸、增物、建筑重建完成动作。

- 交接：记录原持有人→共同接触→接收人独持；尾态原持有人应空手。
- 行走：脚接触地面、路径可通行、人物到场景参照物的关系合理；位移不靠背景整体滑动伪造。
- 接近：推近由相机移动实现时，人物不应为了放大而突然长大或迈向相机。
- 拉焦：注意力转移不应把后景人物搬到前景或把前景物件抹掉。
- 镜面/屏幕：分开记现实区与媒介区；时间延迟需要连续帧证明，单帧只可检验姿态差异。

九个分镜通常分别生成、剪辑。镜间换角度就是切镜，不自动把相邻不同机位图当作同镜首尾去插值。使用首尾帧须确认是同一连续镜头内可实现的状态和路径，并确认后端支持。

使用动作省略或新建立镜时明确标注省略了什么、凭什么恢复方位；剪辑成立不等于相邻静帧能够无缝插值，也不能靠“心象空间”掩盖原本要求精确还原的资产错误。

每个切点检查：人物位置与持有物、视线指向、运动出入画方向、动作阶段、光线和时间。匹配剪辑可有短暂动作重叠，但不能完整重复交接或重复开门。跨轴要有重建空间或连续可读的越轴运动；有意跳切/倒叙依用户设计标记，不硬改为连续剪辑。

音效、对白、音乐只有被请求或原故事需要时才补充；先查后端能力。原对白承载关键剧情时不能为“纯视觉”随意删除，必要时规划后期配音/字幕，不承诺模型正确生成文字。

## 5. 编译成短提示词

图生视频主要描述当前首帧之后发生什么，不重新长篇描述已经存在的脸、房间和画风。一般三至六个清晰句子足够，复杂度由动作决定，不硬设字数。

```text
[一个主要摄影机行为，含方向与目标。]
[首帧可识别的主体，从当前动作阶段完成一个主要事件。]
[一条必要的空间/道具连续性事实。]
[必要焦点或轻微环境运动。]
[可见的落点或结束状态。]
```

固定机位可在首句说明。若人物动作最重要，可先写动作；不要为套格式重复句子。文生视频则还需补充必要的场景、角色和外观信息。

导演意图如“压迫”“暧昧”“释然”要翻译成可见动作、距离、停顿或构图。术语后给出具体行为，不靠“cinematic camera movement”代替设计。

约束优先用事实表达，例如“the single umbrella ends in the right-hand traveler's hand”。只有后端明确支持时才另给负面字段，不让长禁止列表掩盖动作。

## 6. 后端适配

执行前核验选定工具的当前版本和能力：首帧/尾帧/多参考、时长、比例、分辨率、运镜参数、负面字段、声音。记录查询日期。查不到就保留为未验证，不靠模板猜参数。

- 中立版：自然语言描述可见运动；参数单列为设计建议，不提供虚构的 JSON 控制接口。
- Runway：按当前选定型号核验提示词、参考帧、负面字段与运动控制，不把某一代产品的写法泛化到全部型号。[官方指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)
- Veo：按当前选定型号核验负面提示、首尾帧、时长与声音等能力，不靠名称推定接口。[提示指南](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/video-gen-prompt-guide)、[首尾帧文档](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/generate-videos-from-first-and-last-frames)
- 其他后端：读取当前工具说明/官方文档再适配；不用相似服务的参数冒充。

以上链接是执行时查阅的官方入口，不是本次发布已验证的接口能力表。画幅不支持时建议安全区与后期裁切，不能静默拉伸或丢弃关键手部/道具。

## 7. 检查、返工与交付

提交前检查：首帧是否相容、固定/运动是否冲突、位移/转动/拉焦是否混写、运动有无参照和落点、关键动作是否能在计划时长内读懂、是否暴露未知背面、首尾与下一镜是否相容。

实际成片分别检查：相机是否真的执行、主体动作是否完成、实体与空间是否连续。查看首中尾并覆盖接手/松手/跨门等关键时刻；只抽三帧未覆盖事件时，不能宣布全程通过。必要时逐段查看。

失败先降低非必要运动复杂度、修正首帧或矛盾指令，再定向补跑。不得为省事改故事结局；遵守主技能返工上限。

交付顺序：

1. 简短整段轴线/节奏说明。
2. 每镜中文控制卡与独立可复制提示词；别只给九镜共用一句运镜。
3. 已知参数、待适配参数和风险；明确是“提示词检查”还是“已生成并检查”。

需要不同镜头的具体写法时读 [video-prompt-examples.md](video-prompt-examples.md)。示例不是必须轮流使用的运镜配额。
