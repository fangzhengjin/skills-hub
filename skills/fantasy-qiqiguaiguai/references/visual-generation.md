# Visual Generation Module

本文件负责将主 Skill 的内容判断，编译成可执行的图像生成或图像编辑指令。

不要独立运行本模块。先完成主 `SKILL.md` 中的内容发现、模板选择和文案编译。

---

## 1. visual_direction_compile

每次出图前，仅生成一份短视觉简报。不要把全部规则复制到图像 prompt。

内部结构：

```yaml
visual_direction:
  template: T1 | T2 | T3
  source_strategy: preserve_portrait | collage_from_fragments | preserve_full_image
  content_core: 一句话核心创意
  hero_subject: 画面绝对主体
  supporting_assets: 需要使用的其他素材
  headline: 主标题
  supporting_copy:
    - 辅助文字 1
    - 辅助文字 2
  humor_mechanism: 主幽默机制
  composition: 版式关系
  palette: 2-4 个主色
  texture: 纸张、印刷、照片、干净数字界面等
  preservation:
    - 必须保持的内容
  allowed_edits:
    - 允许的编辑
  forbidden:
    - 禁止的变化
  aspect_ratio: "3:4"
```

编译完成后，将其压缩成短 prompt。最终 prompt 应尽量控制在 250–600 个中文字符或等量英文信息内。

---

## 2. 共通视觉规则

### 2.1 画幅

默认：3:4 竖版。

### 2.2 图像层级

必须形成以下层级：

1. 视觉主体。
2. 主标题。
3. 一组辅助信息。
4. 少量装饰。

不可让所有元素同等抢眼。

### 2.3 字体与可读性

- 主标题必须在手机缩略图中可识别。
- 中文不使用过细字体承担主标题。
- 英文主标题优先使用高对比粗体、窄体或强杂志感字体。
- 手写字只承担第二层语气，不承担全部信息。
- 小字不应超过主标题视觉量的 30%。

### 2.4 文字真实性

图像模型可能出现错字。执行时采用以下优先级：

1. 能使用后期排版或可控文字工具时，先生成无字或弱字底图，再添加准确文字。
2. 必须一步成图时，只放最重要的主标题和少量短标签。
3. 长清单、票据、段落文字优先作为视觉符号，不依赖全部可读。
4. 最终交付前复核主标题是否正确。

### 2.5 参考图使用

参考图只用于提炼：

- 排版密度。
- 层级。
- 色彩关系。
- 拼贴方式。
- 编辑气质。

禁止直接复刻：

- 相同人物。
- 相同物件组合。
- 相同标题。
- 相同构图路径。
- 相同品牌账号和 Logo。

# 3. T1｜Portrait Editorial

## 3.1 目标

将人物照片转化为时尚、轻幽默、社交杂志封面。人物必须仍然是视觉中心。

## 3.2 source_strategy

`preserve_portrait`

必须保护：

- 人物身份与面部特征。
- 原有性别表达。
- 发型、服装、配饰。
- 核心姿态与人物关系。
- 肤色与真实皮肤质感。

除非用户明确要求，不得：

- 换脸。
- 变成陌生人或网红脸。
- 改变年龄、性别、种族外观。
- 将双人变成单人。
- 将普通穿搭擅自改成夸张高定。

## 3.3 版式结构

推荐：

- 巨大英文主标题置于人物背后或上方。
- 人物局部可压住文字，建立前后层次。
- 1 个手写副标题。
- 3–6 个小标签。
- 1–3 个与人物生活相关的小物件。

人物面积建议占画面 45%–70%。

## 3.4 色彩

依据人物服装取色，不局限粉色。

推荐组合：

- 钴蓝 + 黑 + 白 + 银。
- 森林绿 + 奶油白 + 黑 + 橙。
- 红 + 蓝 + 米白 + 黑。
- 酒红 + 灰 + 奶油色。
- 纯黑白 + 单一高饱和点色。

## 3.5 文案

- 英文主标题 2–7 个单词。
- 中文只用于短补刀或小标签。
- 幽默保持轻度、时尚、自嘲。

## 3.6 T1 Prompt Compiler

```text
使用输入人像作为唯一人物参考，完整保持人物身份、五官、发型、服装、配饰、姿态和人物数量。制作 3:4 竖版人像编辑海报，人物为绝对主体，具有当代杂志封面与社交内容感。主标题为「{headline}」，使用巨大高对比英文粗体，与人物形成前后遮挡；加入一条克制手写副标题「{secondary_line}」，以及 3–5 个围绕同一状态的短标签：{supporting_copy}。色彩采用 {palette}，加入少量与人物相关的生活物件 {supporting_assets}，不要堆满，不要改脸，不要生成陌生人物，不要品牌 Logo，不要粉色模板化。画面时髦、清晰、有轻微幽默感。
```

## 3.7 T1 失败修复

人物被字压没：减少主标题覆盖面积，提高人物前景层级。

人像像广告模特而非本人：强化“唯一人物参考、身份完全保持、不得重绘陌生脸”。

画面太花：删除一半小物件和标签，只保留 1 个手写元素。

太像模板：从人物服装、动作、场景中提取专属道具和颜色。

# 4. T2｜Object Collage

## 4.1 目标

把互不统一的生活碎片，组织成一个高密度但有中心的幽默内容系统。

## 4.2 source_strategy

`collage_from_fragments`

可以：

- 抠图。
- 裁切。
- 局部放大。
- 重复局部表情或物件。
- 制作票据、清单、警告标签、报表、手绘箭头。

必须保护：

- 原物件的关键识别特征。
- 宠物花色、脸型和表情。
- 真实票据中需要保留的事实信息。

必须处理：

- 手机号、地址、订单号、二维码、真实姓名等隐私。

不得：

- 新增与素材无关的大型主对象。
- 把真实宠物换成另一只相似动物。
- 用随机装饰填满所有空白。

## 4.3 信息架构

推荐结构：

- 1 个巨型主标题。
- 1 个核心对象或 2 个主要切片。
- 3–6 个功能性信息块。
- 1 个结论或底部补刀。

每个信息块必须属于同一个世界观，例如：

- 公司制度。
- 财务报表。
- 研究报告。
- 早餐事故档案。
- 生存说明书。

不得同时混用“宠物公司 + 医院病历 + 旅行攻略 + 游戏 UI”。

## 4.4 色彩

优先 3–4 色高对比体系：

- 黑 + 黄 + 白。
- 蓝 + 黄 + 黑 + 白。
- 橙 + 荧光黄绿 + 黑 + 白。
- 红 + 奶油白 + 黑。
- 绿色 + 白 + 黑 + 单点亮色。

## 4.5 拼贴质感

可选一种主质感：

- 撕纸与复印机颗粒。
- 胶带、便签、手写箭头。
- 报纸、票据、扫描件。
- 干净数字拼贴。

不要同时使用所有质感。

## 4.6 T2 Prompt Compiler

```text
使用输入的生活碎片作为主要素材，制作 3:4 竖版杂物拼贴内容海报。核心创意是「{content_core}」，主标题为「{headline}」。将 {hero_subject} 设为视觉中心，围绕它组织 {supporting_assets}，采用统一的「{system_metaphor}」世界观，用 3–6 个功能性信息块呈现：{supporting_copy}。版式高密度但有明确中心，使用 {palette}，质感为 {texture}，可使用撕纸、票据、便签、箭头和局部放大，但不要无序堆满。完整保持宠物/物件关键特征，隐藏私人信息，不新增无关主体，不使用品牌 Logo。主标题必须清晰，幽默来自内容关系而不是随机装饰。
```

`system_metaphor` 可选：

- 公司与 KPI。
- 财务报表。
- 研究报告。
- 生存说明书。
- 事故档案。
- 日常观察记录。

## 4.7 T2 失败修复

画面杂乱无中心：将主标题缩减为 1 个，删除 30% 信息块，放大主对象。

梗太多：只保留同一系统隐喻下的文字。

中文字错误：改成“先生成底图与文字留白区，再后期准确排版”。

像儿童手账：降低贴纸数量，强化大标题、网格和黑色信息块。

像电商促销：删除价格爆炸贴和商品卖点，改为观察、档案、报告语气。

# 5. T3｜Image Overlay Editorial

## 5.1 目标

保留一张完整照片的力量，通过巨大文字介入，为图片建立新的叙事或黑色幽默。

## 5.2 source_strategy

`preserve_full_image`

最重要规则：

> 原图是成品的底层，不是重绘参考。

必须：

- 保留原图构图、人物、场景、光线和关键事件。
- 文字直接覆盖在原图上。
- 允许遮挡局部，但不得遮掉唯一识别点。

不得：

- 从零生成一张“风格相似”的新照片替代用户原图。
- 把单图拆成大量小拼贴。
- 添加与原图无关的物件。

## 5.3 版式结构

- 一句强主标题，占画面视觉量 30%–55%。
- 文字可跨越主体和背景。
- 小字 2–4 组即可。
- 保留至少一处安静区域。

常用方式：

- 黑白图 + 单一彩色大字。
- 彩色原图 + 黑白高对比字。
- 大字在前，人物局部在字前形成穿插。
- 字体遮挡但不破坏人物面部或关键对象。

## 5.4 T3 Prompt Compiler

```text
将输入照片作为完整且不可替换的底图，严格保留原图人物、场景、构图、光线、空间关系和关键对象，不重绘相似场景，不切碎拼贴。制作 3:4 竖版全图压字编辑海报，主标题为「{headline}」，使用巨大 {headline_style} 字体直接覆盖画面并形成有意的前后遮挡，但不得遮住人物面部或唯一识别点。加入 2–4 组克制小字：{supporting_copy}。色彩采用 {palette}，整体像当代杂志专题封面，图像仍然完整可感知，文字为图片制造第二层含义，不增加无关物件，不使用品牌 Logo。
```

## 5.5 T3 失败修复

原图被重画：强调“不可替换底图、只做排版叠加、reference-preservation”。

文字像字幕：显著增加主标题字号与版式张力，减少小字。

文字挡住主体：重新规划穿插，让面部和关键动作露出。

画面太像普通海报：让主标题与摄影主体建立更大胆的遮挡关系，而不是放在空白处。

# 6. 两阶段生成策略

当工具支持图像编辑或后期文字时，默认采用：

## 阶段 1｜Visual Base

生成或整理无字/少字底图：

- T1：人物 + 标题留白 + 小物件。
- T2：拼贴结构 + 信息块留白。
- T3：保持原图，只确定大字遮挡区域。

## 阶段 2｜Typography Pass

准确添加：

- 主标题。
- 关键辅助字。
- 标签与编号。

此策略优先于一步生成大量中文文字。

用户明确要求快速测试或一步成图时，可以直接生成，但必须降低文字数量。

# 7. 输出给图像工具的最终格式

不要输出 JSON 给普通用户。工具调用内部可使用结构化字段。

用户可见的提示词若被要求，应输出以下短格式：

```markdown
【模板】T2 杂物拼贴版
【核心】把早餐碎片做成一份“早高峰事故档案”
【主标题】淡淡早饭，加重我淡淡的发疯
【画面】三明治、牛奶、闹钟手机、果酱、公交票据组成高密度拼贴
【排版】蓝黄黑白，撕纸、箭头、票据，主标题最大，底部一句补刀
【保护】保留原物件，隐藏隐私，不新增无关主体
【比例】3:4
```

# 8. 批量测试规则

用户要求 T1 / T2 / T3 各生成多张时：

- 每张使用不同题材、不同配色、不同构图。
- 不得只替换标题或颜色。
- T1 三张默认：女性、男性、双人。
- T2 三张默认：宠物、早餐、办公或咖啡。
- T3 三张默认：人物街景、交通或城市观察、动物或自然隐喻。
- 每张均为独立 3:4 成图。
- 批量生成失败或只完成部分时，必须明确报告实际数量，不得声称全部完成。
