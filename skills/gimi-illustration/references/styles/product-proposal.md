## 一句话

理性清晰的现代编辑式产品叙事插画：用裁切人物与手势、具象产品物件、细黑手绘线和克制色块建立层级，让读者先抓结论，再读比较与下一步。

## 画法

**线条与形状** — 近黑细线勾勒文档、卡片、夹板与手势；线条是松弛但受控的真实笔迹，允许轻微不均与连续弧线，不能退化为均匀的 UI wireframe。大块纯色、物件重叠和非对称裁切建立张力；物件必须平面或纸张般轻薄，最多只有一条贴地细阴影。不使用白板支架 / 金属框、统一粗描边、规则网格、整齐排队的卡片墙、立体门架、厚书脊、等距透视或产品渲染式投影。

**信息层级** — 每张只有一个主结论；主卡、主文档、主手势或主物件组承担焦点，次级物件围绕真实协作动作重叠成组。关系通过手势、物件的放入/递交、并置、少量连接线或大小传达，不能用大箭头串成教学流程，也不能靠堆叠小卡片制造“专业感”。

**背景与密度** — 近白中性底；中密度，边缘留出明确呼吸。必须有一块连续的编辑式工作平面、斜置大纸面或桌面线索穿过画面，物件与裁切人物在同一现场发生关系；它不是悬浮卡片组，也不是画在带支架的白板 / 展示架里的信息图。蓝、近黑、薄荷绿构成主视觉，浅珊瑚只作极少量提示。标题必须属于主文档或主卡，不可作为画面顶端的独立海报字。不是纸纹水彩、满屏仪表盘、表格或软件截图。

**内容与动线** — 从结论 / 问题开始，沿单条清晰路径进入比较、门槛或结果。2–5 个短中文标注必须在生成时就是白板、卡片、折页、图表或夹板的版面内容；禁止无字底图后期叠字、悬浮标签或脱离物件的说明栏。一图不承载两条同等权重的阅读路径。

**人物 / 手势预算** — 默认物件优先；只有动作能显著解释关系时才引入人物。最多 2 位人物、2 只可见手；每只手必须经由一整段袖子连接到画面边缘可辨的同一人物。皇家蓝固定为主操作者、薄荷绿固定为协作方；同色不得出现多套无身体归属的手臂。若画面需要表达 3 个以上动作，减少手势，用已摆放的物件、位置和连接线表达。

**IP 与场景** — IP 只可作为小型讲解者或节点旁的辅助角色，不能遮挡信息结构；当没有 IP 时，模块与具名物件必须独立讲清逻辑。

## 无 IP 校准策略

`$IP=none` 时采用 **required style-single**：必须从 `assets/none/examples/product-proposal/` 按 `references/ip/none.md` 的统一四件套选择 1 张并作为 image reference 传入。它不是角色图、不是用户输入，也不复制构图；只锁定本风格的连续编辑现场、松弛近黑线、扁平蓝绿块、边缘裁切、纸件轻薄感与原生中文处理。缺少四件套任一资产或选图时，视为发布包资产缺失，应停止并修复包，而不是让终端用户补图或降级为纯文本。

## 颜色 / 色纪律

| 层 | 规则 |
| --- | --- |
| **IP 角色** | 身份锚点色、服装结构和比例完全跟随设定图；只改变线条质感与整体渲染，不把角色改成蓝灰单色图标。 |
| **场景** | 近白底、近黑线与文字；皇家蓝与近黑为主，薄荷绿为次强调，浅珊瑚最多只作两处小提示。禁止渐变、纸纹、布料纹与柔和水彩阴影。 |
| **标注** | 近黑或白色中文短标注，作为真实物件的印刷版面；允许皇家蓝卡上的白字。禁止彩虹标签、荧光贴纸、大面积色块说明栏和后期叠字。 |

**配色密度：** 低到中；颜色只标示层级、选择或状态，不替代结构与文字。

## 审美方向

要：理性、清晰、扁平、图形化、裁切、编辑感、可扫描
不要：纸纹写实、柔和水彩、拟物 UI、科技霓虹、厚重商务模板、密集小组件

## 绝对不要

- 渐变光效、玻璃拟态、3D 图标、霓虹蓝紫、满屏圆角卡片或装饰性网格。
- 纸纹、水彩晕染、布料颗粒、写实皮肤/发丝、气枪阴影或全局泛黄暖光。
- 规则点阵、半色调网点、波点纹理与孤立小圆点装饰；圆点只可表示真实勾选状态、图表数据点或物件铆钉。
- 白板支架、金属边框、白板笔槽、演示讲台、粗黑居中大标题、画面顶端游离的大标题、编号步骤、连续粗箭头或培训课件式流程图。
- 立体门架、厚重书册、等距透视、强投影、产品渲染感、把物件横向等距排成说明书；不要用 3D 感来表达“门槛”或“流程”。
- 用人脸、角色或吉祥物替代结构关系；用长段落、密集伪文字填满画面。

## Step 0.4 生成（自定义 IP · 本风格样板镜）

> 仅 Step 0 / lazy 校准用；不是配图 Step 3。对用户称“产品方案”。

**必须载入：** 本节 `{STYLE_DNA}` + `{STYLE_ADAPT}` + 已确认的 `reference-character.png`（全身）。

**画面规格：**

- 比例：16:9；角色全身可见，可站在结构图侧边。
- 主题文案（固定）：vibe coding · IP 配图风格样板。
- 场景物件取 2–4：白色规划板、方案卡、折页文档、简洁桌面；皇家蓝与薄荷绿只服务层级。
- 角色不遮挡模块或标注；背景近白，不能画成软件界面、数据仪表盘、纸纹写实或水彩。

**校准专用 prompt 骨架：**

### 校准入库 QA（5 项）

- [ ] 16:9；角色全身可见但信息结构仍是主角。
- [ ] 2–4 个 canonical 物件；皇家蓝、近黑与薄荷绿的层级清楚。
- [ ] 近白底、近黑细线、扁平色块与裁切手势；不是 SaaS UI、传统 PPT、纸纹写实或水彩。
- [ ] 无文章主题、标题、标注、shot 物件或伪数据表。
- [ ] 身份锚点像设定图，角色没有被压成蓝灰图标。

## QA 检查项

**层级与动线**

- 3 秒内先看出主结论，再能跟随一条比较 / 路径关系；不出现两个同等抢眼的焦点。
- 模块、连接线、短标注各自有归属；不靠堆叠卡片、图标或伪数据来填画面。
- 人物或手势不超过 2 位人物 / 2 只手；每只手均可回溯到唯一人物，不能有同色的多套悬空手臂。
- 有 IP 时逐图对照产品方案无 IP 四件套：近白背景、连续编辑式工作平面、近黑细线、皇家蓝 / 薄荷绿扁平色块、纸件轻薄感、边缘裁切和原生中文处理必须同向；IP 只能改变角色身份，不得改变场景画法。

**色纪律与媒介**

- 近黑与皇家蓝为主体，薄荷绿为次强调，浅珊瑚只作小提示；不能出现彩虹色盘。
- 中性底保持干净；无规则点阵、半色调点、纸纹、水彩晕染、写实质感、霓虹、渐变、玻璃质感或 3D 阴影。

**失败信号**

- 像网页 / app 截图、企业 PPT 模板、数据仪表盘、技术后台、带支架的白板培训图，或带立体道具与顶部海报标题的流程说明图。
- 背景退化为纯空白，几个完整 UI 卡片脱离同一工作平面悬浮并置。
- 出现规则点阵、半色调网点或仅为填空的孤立小圆点。
- 标签文字细碎不可读，模块没有主次，或靠虚构数据表假装专业。
- 用粗黑居中标题、编号步骤和连续粗箭头代替编辑式物件关系。
- 角色比结论模块更大、更抢眼，或遮住路径与标注。
- 为表现多个环节而堆出三只以上手，或同色手臂来自不可辨的不同人物。
- 色块失去层级、每张卡都铺底色，或大面积使用珊瑚色。
